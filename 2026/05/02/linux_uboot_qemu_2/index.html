前言

编译(2)中介绍了启动linux流程，但最终的bootscr执行是手动的，autoboot是失败的，本文尝试分析autoboot失败的原因，及解决方法

uboot启动流程简要分析

以下出自uboot文档

  1. 复位后执行对应架构的start.S，位置在arch/arm/cpu/armv7/start.S，目标是进行cpu初始化
  2. 进入 board_init_f()之前的初始化，要求 lowlevel_init() 只能做“最少的事”：没有 global_data、没有 BSS、通常也没有栈，不能碰 SDRAM，也不能用串口；它的职责只是把环境收拾到足以进入 board_init_f()。
  3. init_sequence_f 做前置初始化，malloc、log/bootstage/event/blobs 初始化，然后初始化时钟、定时器、环境变量、波特率、串口和控制台；接着才是显示板卡/CPU 信息、dram_init() 等
  4. 为重定位做内存预留，然后把自己搬到 RAM 里，初始化序列后半段会按顺序预留 FDT、bootstage、bloblist、栈、board info、global data、malloc 区、U-Boot 镜像本体等内存；U-Boot 从“临时位置”切换到“RAM 中的正式位置”
  5. 进入board_init_r()，做重定位后的初始化。 common/board_r.c 里的 init_sequence_r 会继续初始化重定位相关逻辑、设备模型、环境变量重定位、串口/标准 IO、控制台、网络、中断等
  6. run_main_loop() 里反复进入 main_loop()。 bootdelay_process() 会读取 bootdelay 和 bootcmd，autoboot_command() 会在倒计时结束后执行 bootcmd(重点)

bootcmd不是需要执行的脚本，所以报错。bootcmd为环境变量，需要更改，再saveenv

saveenv 问题

savenv完后，重新reset，发现未能生效，同时发现启动时会有warning

需要uboot编译开启环境变量持久化存放，勾选了uboot编译时environment中FAT，设置了environment size

menuconfig选项需要取消Environment in flash

  • 选中Environment is in a FAT filesystem

    Name of the block device for the environment–>mmc

    Device and partition for where to store the environment in FAT–>0:1

    Name of the FAT file to use for the environment–>uboot.env

  • 因为是sd卡，Environment Size和mmc device number、mmc partition number保持默认即可
